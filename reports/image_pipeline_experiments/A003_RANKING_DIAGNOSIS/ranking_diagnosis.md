# A-003.1 — Human feedback and ranking diagnosis

Date: 2026-11-23 (Asia/Saigon). Scope: seven owner-mentioned A-003 items only. Source: existing A-003 downloads, frozen sample, scores, gallery, and production scorer; no search, download, promotion, or production edit. The original A-003 gallery and scores are **pre-FIX-001** historical evidence. `scoring_comparison.csv` records a separate **post-FIX-001** offline run on the existing raw files. The contact sheets in `visual_review/` are inspection aids, not new candidates.

## Feedback provenance

`owner_feedback.json` records seven `OWNER_CHAT_FEEDBACK` statements exactly as supplied with this task. Only hungry and buy have `ICON_BETTER`, eat has `ORIGINAL_BETTER`, and sometimes has `BOTH_BAD`. Receive, book, and house have specific issue reports without an A/B winner. Apple, cat, mountain, car, and happy remain unreviewed by the owner in this task. There is no claimed 12-item gallery export. `sometimes` is `vocab-000083` in the frozen sample and canonical dataset.

The visual suitability labels in `candidate_diagnosis.csv` are this diagnostic's **analyst desk observations**, not owner approvals or legal clearance. Every downloaded candidate file was inspected in a contact sheet and checked against its recorded raw and JPEG hashes. `SUITABLE` means a usable depiction of the target concept at this inspection scale; borderline rights and style choices still require review.

## Actual selection path

1. The A-003 frozen sample takes English/Japanese/Vietnamese and the A-001 effective normal query from the vocabulary evaluation matrix. The icon query is `<english> icon`. A-003 did not call Qwen; production normally generates a query and may apply a semantic override.
2. `imagecollector.search_images` asks DuckDuckGo for up to seven image results per query. A-003 saves result metadata, source URLs, and original retrieval order.
3. A-003 downloads each candidate to `.img` and creates a gallery JPEG. Failed downloads are excluded from scoring. The original A-003 JPEGs were normalized before FIX-001; they remain historical files.
4. A-003 calls `SiglipImageScorer.score_batch(query, raw_paths)` separately for each arm. Thus the exact original SigLIP text is the search query, such as `receive action` or `receive icon`, **not** the Japanese/Vietnamese sense or a shared vocabulary description. A secondary bare-English score was recorded but never used to select.
5. `score_batch` opens raw images, now composites transparency onto white via `flatten_to_rgb`, and passes them to the cached SigLIP processor. The processor config resizes to 384×384, rescales and normalizes pixels; no crop step is configured. The code does not explicitly crop. It returns `logits_per_text[0]` as raw float scores: no softmax, sigmoid, candidate normalization, or educational-quality score.
6. A-003 uses `max(query_score)` and production sorts the same scores descending. There is no semantic, watermark, text leakage, composition, or absolute-score rejection gate after a successful download. If no scored selection exists, A-003 falls back to the first downloaded candidate. Production has a no-candidate failure path, but no post-ranking `NO_SUITABLE_IMAGE` decision.
7. FIX-001 corrects alpha compositing in both scoring and final JPEG normalization. The production selection code otherwise still scores the search query and takes top-1.

Source: `collect data script/imagecollector.py` (`search_images`, `choose_image_result_with_siglip`, `normalize_image_to_jpeg`), `collect data script/image_scorer.py` (`flatten_to_rgb`, `score_batch`), A-003 `run_a003.py`, and the local model `preprocessor_config.json`. The post-fix diagnostic uses the same `SiglipImageScorer`, model and score formula; exact meaning descriptions were frozen in `owner_feedback.json` **before** running it. One description is applied to both arms of each word. Scores from different text prompts are only useful for ranking within their prompt, not as absolute quality thresholds.

Top-3 within each arm and every candidate score/rank are in `scoring_comparison.csv`. After FIX-001, query scoring changed the icon top-1 for **buy** from I-06 to I-04, both text-heavy; other six items' two top-1 choices stayed the same. In the 14 arm-level pools, the analyst-marked suitable top-1 count is **4/14** with original query scoring, **4/14** with post-fix query scoring, and **6/14** with meaning scoring. A suitable image appears in the top-3 of **6/14**, **6/14**, and **7/14** respectively. Across both pools under one common meaning prompt, top-1 is suitable for **4/7** words; the three misses are house, buy, and sometimes. These are descriptive counts on this chosen sample, not an accuracy estimate.

The meaning prompt helps **receive**, **book**, and **hungry** surface useful alternatives, and moves the complete house from sixth to third within NORMAL. It still puts a house-construction chart first, chooses an Action store over shopping icons for **buy** across pools, and cannot create a useful **sometimes** or **eat icon** candidate. Thus scoring against vocabulary meaning has a measured benefit for some items but is not a standalone fix. A text/quality rejection step and a human choice remain necessary.

## Limits

These 12 A-003 IDs were chosen rather than randomly sampled; this task reviews seven owner-mentioned words. Candidate suitability here is a single analyst visual judgment. Search result ordering was not rerun, and no new image was added. The old gallery shows pre-fix JPEGs, while the diagnostic scores raw images with the fix. The owner's `receive` size remark lacks an exact candidate or screenshot reference. No owner decision exists for the other five A-003 items, and no explicit A/B winner exists for receive, book, or house.
